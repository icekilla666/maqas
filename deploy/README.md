# Переход работающего приложения на https://maqas.ru

Сервер приложения: `72.56.250.175`. Эти действия выполняются **на сервере**, в той же папке проекта, из которой приложение запускалось раньше. Пока файлы сертификата не подготовлены, не перезапускай nginx с новым конфигом.

## 1. Связать домен с сервером

В панели управления DNS домена добавь или исправь запись:

| Тип | Имя | Значение |
| --- | --- | --- |
| A | @ (или пустое поле) | 72.56.250.175 |

Сохрани существующие MX/TXT-записи почты и проверки домена. Если у `maqas.ru` есть AAAA-запись, она должна вести на работающий IPv6 этого же сервера; иначе удали ошибочную AAAA-запись. Изменения DNS применяются не сразу.

Основной адрес — **maqas.ru без www**. Для `www.maqas.ru` настроено перенаправление на основной адрес; проверенный сертификат покрывает оба имени. DNS-запись `www` должна вести на тот же сервер (A или CNAME на `maqas.ru`).

В сетевых правилах хостинга должны быть разрешены входящие TCP-порты **80 и 443**. Порт SSH оставь доступным. Не запускай второй nginx на хосте: порты сайта обслуживает контейнер `nginx`.

## 2. Подготовить купленный SSL

Покупка сертификата и его выпуск — разные шаги. В панели продавца SSL выполни проверку владения доменом, если она ещё не завершена. Скачай выпущенный сертификат и цепочку промежуточных сертификатов в формате PEM для nginx.

Приватный ключ — файл, созданный вместе с запросом CSR. Он может находиться у хостинга, если CSR создавался через его панель. Новый случайный ключ к уже выпущенному сертификату не подойдёт: при утрате ключа потребуется перевыпуск сертификата.

В папке проекта на сервере должны получиться файлы:

```text
deploy/certs/fullchain.pem  — сертификат maqas.ru, затем промежуточные сертификаты
deploy/certs/privkey.pem    — соответствующий приватный ключ
```

Если продавец выдал сертификат и цепочку отдельно, объедини их в указанном порядке. Имена исходных файлов ниже — пример, замени их своими:

```bash
mkdir -p deploy/certs
cat maqas.ru.crt intermediate-ca.crt > deploy/certs/fullchain.pem
cp maqas.ru.key deploy/certs/privkey.pem
chmod 600 deploy/certs/privkey.pem
chmod 644 deploy/certs/fullchain.pem
```

Ключ для автоматического запуска nginx должен читаться без запроса пароля. Эти файлы исключены из Git и подключаются в контейнер только для чтения. Не присылай содержимое ключа в чат.

## 3. Сохранить существующую базу и настройки

Не меняй папку проекта, имя Compose-проекта (`-p` / `COMPOSE_PROJECT_NAME`) и имя тома базы. В конфиге сохранены сервис `db`, контейнер `maqas_postgres` и том `postgres_data`. Фактическое имя тома обычно содержит префикс Compose-проекта.

Проверь текущее имя проекта и том, не выводя пароли:

```bash
docker compose ls
docker inspect maqas_postgres --format '{{range .Mounts}}{{println .Name .Destination}}{{end}}'
```

Перед обновлением сделай резервную копию работающей базы. Эти команды используют данные из контейнера, не показывая пароль:

```bash
mkdir -p deploy/backups
chmod 700 deploy/backups
umask 077
docker exec maqas_postgres sh -c 'pg_dump -U "$POSTGRES_USER" -d "$POSTGRES_DB" -Fc' > deploy/backups/before-https.dump
test -s deploy/backups/before-https.dump
docker exec -i maqas_postgres pg_restore --list < deploy/backups/before-https.dump > /dev/null
```

Сохрани копии прежних `docker-compose.yml`, `nginx.conf` и рабочей конфигурации вне перезаписываемых файлов. Файл резервной копии базы содержит пользовательские данные; не добавляй его в Git.

Создай **корневой** `.env` по `.env.example`, если его ещё нет. Укажи **текущие** логин, пароль и имя существующей базы. Пароль раньше был записан прямо в `docker-compose.yml`; теперь он берётся из `.env`. Не меняй пароль при этом переходе: переменная `POSTGRES_PASSWORD` не меняет пароль уже созданной базы.

```dotenv
POSTGRES_USER=myuser
POSTGRES_PASSWORD=текущий_пароль_базы
POSTGRES_DB=maqas_database
```

Compose формирует `DATABASE_URL` из этих значений и адреса `db:5432`. Для этой схемы логин, пароль и имя базы должны быть без URL-спецсимволов (`@`, `:`, `/`, `%` и т. п.). Пароль из прежнего конфига подходит. Если реальные настройки сервера другие или база внешняя, сначала адаптируй `DATABASE_URL`, не переключай приложение на другую базу.

**Существующий `backend/.env` сохрани.** Не заменяй его примером: там рабочие секреты, SMTP и Cloudinary. `backend/.env.example` нужен только как справочник или для новой установки. Compose переопределяет только адрес базы и `VERIFY_EMAIL_URL=https://maqas.ru/verify-email`.

## 4. Проверить и переключить приложение

Нужен Docker Compose v2 (`docker compose version`). Команды ниже выполняй в существующей папке проекта и с тем же именем Compose-проекта, что раньше.

После переноса новых файлов, настройки `.env` и размещения сертификата:

```bash
bash deploy/check.sh
docker compose build backend frontend
docker compose up -d --wait --wait-timeout 180
docker compose ps
```

Выполняй команды по очереди: при ошибке предыдущей команды не переходи к следующей. Сборка выполняется до перезапуска работающих контейнеров. При переключении возможен короткий перерыв. `check.sh` проверяет срок, домен, цепочку, соответствие ключа сертификату, Compose и `nginx -t`; для последнего создаёт временный контейнер без публикации портов. Работающие сервисы он не перезапускает.

**Не выполняй `docker compose down -v`: эта команда удаляет том базы.** Для обновления достаточно `up -d`. Этот переход не запускает миграции Alembic; механизм запуска базы в текущем backend остаётся прежним.

Проверка после запуска:

```bash
curl -I http://maqas.ru
curl -I https://maqas.ru
curl -fsS -o /dev/null -w '%{http_code}\n' https://maqas.ru/api/openapi.json
```

Ожидается: HTTP → `308` на HTTPS, главная → `200`, API → `200`. Открой сайт и проверь вход, обновление страницы поста по прямой ссылке, загрузку картинки и отправку письма подтверждения. При переходе с IP на домен понадобится заново войти: браузер хранит данные входа отдельно для каждого адреса.

Если что-то не стартовало:

```bash
docker compose logs --tail=100 nginx backend frontend db
```

Не отправляй логи публично целиком: существующий backend может выводить данные запросов. Если нужен откат, восстанови сохранённые конфиги и прежнюю версию кода, пересобери образы и запусти `up -d` с тем же томом; SSL-переход не требует отката схемы базы.

## Что настроено

- nginx принимает HTTP/HTTPS и перенаправляет HTTP на `https://maqas.ru`.
- `/api/…` идёт в FastAPI с сохранением префикса `/api` и заголовков исходного протокола.
- `/api/ws/chats` поддерживает WebSocket Upgrade; будущий клиент чата должен использовать `wss://maqas.ru/api/ws/chats` с авторизацией по текущему API.
- Uvicorn установлен с WebSocket-зависимостями. Он работает одним процессом: текущие подключения чата хранятся в памяти процесса.
- Фронтенд обращается к API на том же домене. Локальный `.env` не попадает в Docker-сборку; адрес HTTP через IP не зашивается в production JavaScript.
- PostgreSQL доступен контейнерам по `db:5432`, порт 5432 наружу не опубликован.
- Контейнеры автоматически перезапускаются; backend ждёт готовности PostgreSQL, nginx — backend и фронтенда.
- Для `refresh_token` nginx добавляет Secure. Изменять бизнес-логику авторизации для этого перехода не потребовалось.

## Сборка на сервере с небольшим объёмом памяти

На сервере с 1 ГБ памяти фронтенд можно собрать на своём компьютере:

```bash
cd frontend
VITE_API_URL= npm run build
```

Передай содержимое `frontend/dist` в одноимённую папку проекта на сервере. Затем из корня проекта **на сервере**:

```bash
docker build -f deploy/frontend.Dockerfile -t maqas-frontend ./frontend
docker compose build backend
bash deploy/check.sh
docker compose up -d --no-build --wait --wait-timeout 180
```

Имя образа `maqas-frontend` соответствует текущему Compose-проекту `maqas`. Файл `frontend.Dockerfile.dockerignore` разрешает копирование готового `dist` только для этой сборки. Обычный Dockerfile по-прежнему умеет собирать фронтенд полностью.

## Продление сертификата

Купленный сертификат продлевается у его продавца. После выпуска нового замени файлы в `deploy/certs`, затем выполни:

```bash
bash deploy/check.sh
docker compose exec nginx nginx -t
docker compose exec nginx nginx -s reload
```

Каталог смонтирован целиком, поэтому nginx увидит и файлы, заменённые через переименование. Автоматическое продление не настроено: оно зависит от продавца SSL.

Документация: [HTTPS и цепочка сертификатов nginx](https://nginx.org/en/docs/http/configuring_https_servers.html), [WebSocket в nginx](https://nginx.org/en/docs/http/websocket.html), [ожидание готовности сервисов в Compose](https://docs.docker.com/compose/how-tos/startup-order/).
